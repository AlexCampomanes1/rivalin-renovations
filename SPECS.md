## Roadmap (post-detachment)

These are why the site was detached — work happens here, then the proven
pattern gets ported back into the Ultra Flow builder as an opt-in module
(only for verticals that need it: home reno, painting, cleaning, landscaping,
auto detailing, fitness, dental, etc.).

### 1. Before & After gallery (priority)
- Drag-handle slider revealing "after" over "before" on the same frame
- Stack two `<img>`s, clip-path on the after image, vertical handle with
  chevrons, also keyboard-driven via hidden `<input type=range>`
- Touch-friendly on mobile (no scroll-jank)
- Multiple pairs, each with optional label + duration
- Pure CSS + ~30 lines of vanilla JS, no libraries

### 2. Standard gallery (visual redesign)
Current `tile` style is OK but generic. Decide between:
- **Masonry** — varying tile heights, more "portfolio" feel
- **Filmstrip** — horizontal scroll, full-bleed
- **Lightbox** — tap-to-zoom with arrow navigation

Whatever wins ships back to the builder as the new default for `galleryStyle`.

### 3. Local admin uploader
Tiny static admin page (or single-file Node script) that drops new images
into `assets/gallery/` and `assets/before-after/` and updates a JSON
manifest. No login required for local-only use; gate later if hosted.

Manifests:
- `assets/gallery-manifest.json` → array of `{ src, alt, caption }`
- `assets/before-after-manifest.json` → array of `{ id, before, after, label, durationDays }`

`index.html` reads the manifests on load and renders accordingly.

### 4. Real hosting
Move from local file:// to a real host. Options:
- Own subdomain on AccelerateIQ DNS (e.g. `rivalin.accelerateiq.ca`)
- Client's own domain (preferred — pure transfer of ownership)
- Static blob container + AFD (same pattern as `ultraflow.accelerateiq.ca`)

Once hosted: remove the "(Site not yet deployed — temporary preview)" line
from the footer, and decide on QR + Ultra Flow attribution.

## Coding conventions for this folder

- **Single HTML file** for now. Split only when a real router or templating
  need appears.
- All CSS inline in `<style>` at the top of `index.html`. Edit in place.
- All JS inline at the bottom of `<body>`.
- Image filenames are stable — never rename without `git mv`.
- `project.json` is read-only context. Do not mutate it; update SPECS.md
  instead when client details change.
- Commit early, commit often. Each section/feature gets its own commit.

## Re-attaching to the builder (escape hatch)

If for some reason this needs to go back into the Ultra Flow pipeline:
1. Strip the local CSS additions that don't fit the builder's template
2. Re-upload `assets/logo-*.jpeg` to `ultraflowuploads/uploads/proj_4e713c3e/`
3. PATCH `generatedHtml` back via `PATCH /api/projects/proj_4e713c3e`
   (the endpoint accepts `generatedHtml` since 2026-05-22)
4. Set `project.status = 'built'` if it was deleted from `projects.json`

Don't do this casually — it defeats the whole point of detaching.
